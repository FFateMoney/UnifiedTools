# 系统状态(概览页)

取代原来 State 的监控显示。代码在 `app/UnifiedTools/Status/`:

- `SystemStats.swift`:各项数据的采集函数
- `SystemMonitor.swift`:每 2 秒采样一次,保存最近 60 次的历史
- `SystemStatusView.swift`:概览页界面

主窗口左边栏现在是:**概览**(本页)、**操作**(原来概览里的快捷操作和权限检查)、应用管理、设置。

## 显示的内容

页头显示芯片型号、机型、核心数、内存容量、macOS 版本、已开机时间。下面是卡片:

| 卡片 | 内容 |
|---|---|
| 处理器 | 总占用百分比、用户和系统占比、最近一分钟曲线 |
| 内存 | 已用 / 总量、应用、联动(wired)、压缩三段占比条、曲线、内存压力、交换用量 |
| 存储 | 启动盘已用、可用、总量。"可用"用的是访达同款口径(含系统可清除的空间) |
| 温度 | 处理器核心最高和平均温度、电池温度、固态硬盘温度、系统散热状态 |
| 网络 | 下载和上传速度、两条曲线(Wi-Fi 与有线合计) |
| 图形处理器 | 占用百分比和曲线,没有该数据的机器不显示 |
| 电池 | 电量、充电状态、剩余时间、最大容量、循环次数、适配器功率,台式机不显示 |

只有打开概览页时才采样,离开页面或关闭窗口就停止,所以不会在后台耗电。

## 数据来源

| 项 | 来源 |
|---|---|
| CPU | `host_statistics`(`HOST_CPU_LOAD_INFO`)两次采样的差 |
| 内存 | `host_statistics64`(`HOST_VM_INFO64`);已用 = 应用 + 联动 + 压缩,和活动监视器同口径;交换和压力来自 `sysctl` |
| 存储 | `URLResourceValues` 的总容量和 `volumeAvailableCapacityForImportantUsage` |
| 网络 | `getifaddrs` 里 `en*` 接口的 32 位字节计数,用环绕减法算差 |
| GPU | IORegistry 里 `IOAccelerator` 的 `PerformanceStatistics` |
| 电池 | `IOPS` 加 `AppleSmartBattery`;新系统把容量放在 `BatteryData` 字典里 |
| 温度 | IOKit 的 HID 温度传感器(未公开头文件的符号),不需要管理员权限。取名字含 `tdie` 的作为核心温度,`tcal` 是校准读数,不算 |
| 散热状态 | `ProcessInfo.thermalState` |

## 在本机上实测的读数(开发时核对)

M5 芯片,CPU 约 15%,内存已用 12.1 GB / 16 GB(应用 5.2、联动 2.6、压缩 4.3),存储可用约 138 GB / 494 GB,GPU 32%,电池 94%、循环 90 次,44 个温度传感器(核心约 28°C,电池约 24°C,固态硬盘 26°C)。与活动监视器的口径一致。

## 没有做的

- **风扇转速**:要读 SMC,需要私有接口;无风扇机型(如 MacBook Air)本来就没有
- **蓝牙设备电量**、**每核心占用**、**占用资源最多的进程**
- **功耗**(瓦数):`powermetrics` 需要管理员权限
- 菜单栏里常驻显示数值(原 State 的主要形态)。现在只在主窗口概览页里看

## 已知限制

- 温度用的是 IOKit 里没有公开文档的符号,系统升级后可能失效;失效时温度卡片只剩电池温度和散热状态,不会崩溃
- 网络速度是接口计数的差值,不区分应用,也不含 VPN 隧道本身的流量重复计算(只统计 `en*` 物理接口)
- 内存"已用"口径和第三方工具可能有几百 MB 差别

- [ ] 打开一个吃 CPU 的程序,处理器卡片的数字和曲线随之上升
- [ ] 内存已用数字与活动监视器的"已使用内存"接近
- [ ] 存储可用与访达里"可用"接近
- [ ] 下载一个大文件,网络卡片的下载速度跳起来
- [ ] 温度卡片有数值,跑重负载后核心温度上升
- [ ] 笔记本显示电池卡片,台式机不显示
- [ ] 切到别的页面后 UnifiedTools 的 CPU 占用降到接近 0
- [ ] "操作"页有原来的快捷操作和权限检查
