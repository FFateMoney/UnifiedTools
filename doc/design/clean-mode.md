# 清洁模式(CleanMode)

对应里程碑 M2。代码在 `app/UnifiedTools/Modules/CleanMode/`。

## 行为

菜单栏提供三个入口:

| 入口 | 屏幕 | 键盘 | 退出方式 |
|---|---|---|---|
| 仅黑屏 | 每块屏幕盖全黑窗口 | 正常 | 长按鼠标左键 3 秒,或超时 |
| 仅锁定键盘 | 正常,顶部显示小面板 | 全部失效 | 点面板上的"结束",或超时 |
| 黑屏并锁定键盘 | 同"仅黑屏" | 全部失效 | 长按鼠标左键 3 秒,或超时 |

进入后菜单里只剩"结束清洁模式"。超时默认 120 秒,在设置窗口的"清洁模式"一栏可调(30 到 600 秒)。

鼠标和触控板始终可用,不提供屏蔽选项,否则键盘锁定后就没有退出手段。

## 实现要点

- 黑屏:`BlackoutController`。窗口层级 `CGShieldingWindowLevel`,无边框;隐藏 Dock 和菜单栏;隐藏光标;`IOPMAssertion`(`PreventUserIdleDisplaySleep`)防止显示器休眠,退出时释放;屏幕插拔时重建窗口
- 键盘锁定:`KeyboardBlocker`。会话级 `CGEventTap`(`defaultTap`),丢弃 `keyDown`、`keyUp`、`flagsChanged` 和类型 14 的系统功能键(音量、亮度、播放);收到 `tapDisabledByTimeout` 或 `tapDisabledByUserInput` 立即重新启用
- 事件拦截随进程存在,应用崩溃或退出后键盘自动恢复
- 需要的权限:辅助功能、输入监控。缺少时弹窗引导,不会进入半成功状态(黑屏不会在键盘锁定失败时单独启动)

## 已知限制

- 电源键、Touch ID 键拦不住
- 输入密码等触发系统"安全输入"时,事件拦截会失效
- 用 `Cmd+Option+Esc` 等由系统层处理的组合键是否被拦截,待实测

## 已修复的问题

- 仅锁定键盘时应用在约 1 秒后崩溃(`EXC_BREAKPOINT`,堆栈在 AppKit 的 `updateConstraintsIfNeeded`)。原因是顶部面板里的倒计时文字每秒变化,`NSHostingView` 默认会据此调整窗口尺寸,在布局过程中触发 AppKit 异常。处理:`sizingOptions = []`,面板和内容都固定为 380×44。此修复尚未实测

## 手动测试清单

首次测试前先在设置窗口为"辅助功能"和"输入监控"授权。每项测完应能恢复正常使用。

- [ ] 仅黑屏:屏幕全黑,光标隐藏,键盘可用;长按鼠标左键 3 秒后恢复
- [ ] 仅锁定键盘:任意按键无反应,媒体键无反应;点"结束"恢复
- [ ] 黑屏并锁定键盘:屏幕全黑且按键无反应;长按鼠标 3 秒后两者都恢复
- [ ] 超时:把时间调到 30 秒,确认到点自动恢复
- [ ] 未授权时点锁键盘:弹出授权提示,屏幕不变黑
- [ ] 外接显示器:所有屏幕都被覆盖
- [ ] 黑屏期间显示器不休眠(超过系统休眠时间后仍亮着,黑屏窗口仍在)
- [ ] 重新编译后,辅助功能和输入监控授权是否需要重新勾选(写入 `doc/setup/signing.md`)
