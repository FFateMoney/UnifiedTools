# 快捷键自定义

代码在 `app/UnifiedTools/Core/HotkeyCenter.swift` 和 `app/UnifiedTools/App/HotkeyRow.swift`。

## 默认快捷键

| 功能 | 默认 |
|---|---|
| 截图 | `⌃⌥A` |
| 剪贴板历史 | `⌘⇧V` |
| 黑屏并锁定键盘 | `⌃⌥⌘K` |

## 修改方法

设置窗口的"快捷键"一栏,点某一行的按键组合,按下新的组合即生效;`Esc` 取消录制;出现 ↺ 按钮时点它恢复默认。修改后立刻生效并保存,重启应用后仍保留。菜单栏里显示的快捷键也会跟着变。

## 规则

- 必须包含 `⌘`、`⌃`、`⌥` 之一,功能键 F1 到 F12 除外。单独的字母不允许,否则会劫持所有应用里的正常输入
- 录制期间所有已注册的全局快捷键会被暂时撤销,避免录制时误触发;录制结束后恢复

## 冲突检测

每个快捷键旁会显示状态:

- **被其他应用占用**:另一个应用已用 Carbon 方式注册了同一组合,我们注册失败
- **与 macOS 系统快捷键冲突**:读取系统偏好 `com.apple.symbolichotkeys`,发现同一组合被系统绑定。这种情况下注册能成功,但按下时系统和我们**都会响应**。⌘⇧A 就是这样:系统的"拷贝所选区域的图片到剪贴板"默认或被设置成了它,表现为先弹出系统截图的覆层
- **注册失败**:附系统错误码

检测不到的情况:其他应用不用 Carbon 注册、而是用事件监听实现的快捷键(例如 iShot 之类),它们不会被报告为冲突,但也会同时响应。遇到"按一次出现两个东西"时,先看是不是还有别的工具在响应同一个组合。

## 排查"按一次出现两个响应"的办法

监视屏幕上的高层窗口和进程,看谁在快捷键按下的瞬间出现;`ps` 看进程的父进程。本项目就是这样发现系统 `screencapture` 进程(父进程 SystemUIServer)被同一个组合触发的。

## 手动测试清单

- [ ] 设置窗口的"快捷键"一栏列出三个快捷键,状态都正常
- [ ] 点截图的快捷键,按 `⌃⌥S`,菜单栏里变成 `⌃⌥S`,按它能截图,旧的 `⌃⌥A` 不再响应
- [ ] 录制时按单独的字母:发出提示音,不会被接受
- [ ] 录制时按 `Esc`:取消,保持原来的快捷键
- [ ] 把截图设成 `⌘⇧A`:显示"与 macOS 系统快捷键冲突"
- [ ] 把剪贴板设成和截图一样的组合:后注册的显示"被其他应用占用"
- [ ] 点 ↺ 恢复默认
- [ ] 重启应用后自定义的快捷键还在
